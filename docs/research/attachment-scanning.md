# Research: safe low-cost pipeline for unmodified mixed-format attachments

## Summary

A safe storage and quarantine design is feasible with the existing DigitalOcean Spaces subscription, but **production malware scanning of every attachment up to 32 MiB cannot be verified within the hard US$10/month total deployment ceiling**. The already-decided US$5 application + Neon Free + US$5 Spaces baseline consumes that ceiling; ClamAV needs substantially more memory than that application has, while the managed services whose privacy and production terms fit either start above the entire ceiling or have no verifiable price.

**Recommendation:** do not enable attachments at launch under the present ceiling. Preserve the pipeline below as the implementation target, and enable it only after funding at least a separate 4 GiB scanner (currently US$24/month for the smallest 4 GiB DigitalOcean Droplet) or procuring a private managed-scanning plan. Do not weaken “scanned before publication” into best-effort scanning or send Review files to a public malware corpus.

## Constraints inherited from the decision map

- Issue [#30](https://github.com/ust-archive/ust-rankings/issues/30) asks for private direct uploads to Spaces, unmodified common image/audio/video/document files, a 32 MiB-per-User stored-object quota, and a US$10 total ceiling. It has no comments.
- [#15](https://github.com/ust-archive/ust-rankings/issues/15#issuecomment-5352289213) establishes either Workers Paid + D1 + Spaces at US$10 total or a US$5 App Platform service + Neon Free + Spaces; the latter is the later-selected PostgreSQL-compatible direction.
- [#23](https://github.com/ust-archive/ust-rankings/issues/23#issuecomment-5352831185) selects Neon Free PostgreSQL and requires attachment metadata/associations and related state changes to be transactional.
- [#16](https://github.com/ust-archive/ust-rankings/issues/16#issuecomment-5352294258) and [#25](https://github.com/ust-archive/ust-rankings/issues/25#issuecomment-5353063152) require disclosure of object-storage/processors and cross-border handling; prohibit malicious, confidential, unlawfully shared, and high-risk personal material; allow operators to quarantine/remove attachments; and leave attachment rights/licensing to #26. Public Review publication is immediate, but that does not require an attachment to become public before it clears scanning.

## Findings

1. **Severity: blocker — malware scanning does not fit the ceiling.** ClamAV recommends at least 3 GiB RAM and 5 GiB free disk; its official container guidance says signatures alone use upwards of 1.2 GiB and concurrent database reload can briefly double that, recommending 4 GiB. The chosen 512 MiB application cannot safely host it. DigitalOcean currently lists a 4 GiB basic App Platform instance at US$40/month and the smallest 4 GiB Droplet at US$24/month, before the existing US$5 Spaces bill. [ClamAV requirements](https://docs.clamav.net/Introduction.html) [ClamAV container memory/update behavior](https://docs.clamav.net/manual/Installing/Docker.html) [App Platform pricing](https://docs.digitalocean.com/products/app-platform/details/pricing/) [Droplet pricing](https://www.digitalocean.com/pricing/droplets)

2. **Severity: blocker — no evaluated managed service provides a verified production-safe 32 MiB path inside the remaining US$0.** Cloudmersive's free tier allows 600 calls/month but only 3.5 MB per file; its production guidance says premium plans start at US$19.99/month. VirusTotal's free public API is non-commercial, must not substitute for antivirus, and standard uploads can be shared with premium customers; Private Scanning is paid, quote-priced, and notably does not include partner antivirus verdicts. OPSWAT permits free integration only for demo/personal use; private scanning is paid. AWS GuardDuty Malware Protection applies only to an Amazon S3 bucket owned by the AWS account, not an S3-compatible Spaces bucket. [Cloudmersive pricing](https://www.cloudmersive.com/pricing-small-business) [VirusTotal API terms](https://docs.virustotal.com/docs/api-overview) [VirusTotal file sharing](https://docs.virustotal.com/docs/how-it-works) [VirusTotal Private Scanning](https://docs.virustotal.com/docs/private-scanning) [OPSWAT public API licensing](https://www.opswat.com/docs/mdcloud/integrations/public-apis) [OPSWAT private scanning](https://www.opswat.com/docs/mdcloud/operation/private-scanning-with-metadefender-cloud-apis) [GuardDuty scope](https://docs.aws.amazon.com/guardduty/latest/ug/gdu-malware-protection-s3.html)

3. **Spaces supports the required private upload/quarantine primitives.** Objects are private by default; private objects are accessible only by authenticated requests or presigned URLs. Spaces supports S3 Signature V4 presigned URLs, private/public object ACLs, `CopyObject`, CORS, and lifecycle expiry/removal of incomplete multipart uploads. A single origin `PUT` supports up to 5 GB, so the 32 MiB limit needs no multipart upload. Signed uploads must use the origin endpoint: presigned uploads sent to the CDN are capped at 7.91 MiB. [Permissions and presigned URLs](https://docs.digitalocean.com/products/spaces/how-to/set-file-permissions/) [S3 compatibility](https://docs.digitalocean.com/products/spaces/reference/s3-compatibility/) [Spaces limits](https://docs.digitalocean.com/products/spaces/details/limits/)

4. **CORS is an opt-in browser gate, not authorization.** Configure one exact production application origin (and explicit preview origins only when needed), allow only `PUT` and `HEAD`, allow only the signed request headers, and expose `ETag` if completion uses it. Spaces explicitly says ACLs and bucket policies still apply after CORS. Do not enable wildcard origins, `GET`, `DELETE`, or credentials. Purge the CDN after CORS changes because old cached responses can lack the new headers. [Spaces CORS](https://docs.digitalocean.com/products/spaces/how-to/configure-cors/)

5. **Presigned uploads require application-side quota reservation and post-upload verification.** In one PostgreSQL transaction, authenticate the active User, lock/recalculate their usage, reserve the declared byte count, and create a `pending_upload` row with an opaque UUID key under `quarantine/`; count clean, quarantined, and active reservations toward exactly 33,554,432 bytes. Issue a short-lived, single-key presigned origin `PUT` that fixes the private ACL and declared `Content-Type`. After the client signals completion, `HEAD` the object and reject/delete it if the key, byte length, or required metadata differs. Random immutable keys prevent filename traversal and overwrite of another attachment. Expired reservations are released only after confirming the object is absent/deleted. A presigned URL delegates exactly the signer’s authority for its lifetime, so it is not itself a quota control.

6. **Quarantine and promotion should preserve bytes.** Keep quarantine objects private and absent from Review output. The scanner streams the object once, computing SHA-256 while identifying and scanning it; never execute it, mount it, or invoke native viewers. On a clean result, server-side `CopyObject` the same bytes to a new immutable `public/<attachment-uuid>/<content-hash>` key with `public-read` and canonical response metadata, verify destination size/hash metadata, transactionally mark the attachment clean/associated, then delete the quarantine copy. A lifecycle rule should expire `quarantine/` objects after a short recovery window and remove incomplete multipart uploads; lifecycle is a backstop, while the database worker performs timely orphan cleanup. Spaces lifecycle rules support time-based expiry but not tag-based rules, so use prefixes. [Spaces compatibility matrix](https://docs.digitalocean.com/products/spaces/reference/s3-compatibility/)

7. **“Exact content identification” has two separate meanings.** Exact byte identity is achievable with SHA-256 plus byte length. A file's semantic format cannot be proven universally from its filename or claimed MIME type: the shared-mime-info specification resolves conflicts using content magic and notes that container formats such as Ogg/AVI need content inspection. Use a maintained libmagic/shared-mime-info database, require agreement among allowed extension, magic-detected MIME/container, and a lightweight structural parser for ambiguous containers (for example, ZIP-based OOXML), and reject unknown, polyglot/ambiguous, malformed, encrypted/password-protected, executable, archive, or nested-container input. Store claimed MIME/name separately from detected MIME. Identification is an allowlist gate, not a substitute for malware scanning. [Shared MIME-info specification](https://specifications.freedesktop.org/shared-mime-info/latest-single)

8. **The viable format policy is preservation plus conservative rejection, not transcoding.** Permit an explicit tested list of common raster images, PDF, plain text, office documents, and audio/video containers only when detection and structural checks agree. Preserve accepted bytes unchanged. SVG, HTML, JavaScript, executables, disk images, archives, macro-enabled Office files, and encrypted documents should be rejected initially because safe inline behavior or complete inspection cannot be guaranteed cheaply. This still allows mixed formats, but “all common files regardless of inspectability” is incompatible with a fail-closed scanner.

9. **Signature freshness and scan evidence are production requirements.** A dedicated ClamAV scanner would persist `/var/lib/clamav`, run `freshclam`, and record engine version, signature version/time, SHA-256, detected MIME, result, attempts, and timestamps. ClamAV says `freshclam` downloads signed official databases and applies differential updates, replacing a corrupt database with a full download; old/EOL images may become unable to update. Alert on update failure and stop publishing new attachments once definitions exceed a defined freshness limit. Disable concurrent reload only if memory pressure requires it, accepting a short scan pause rather than an OOM. [Signature updates](https://docs.clamav.net/manual/Usage/SignatureManagement.html) [Container/EOL guidance](https://docs.clamav.net/manual/Installing/Docker.html)

10. **Delivery must be download-only and origin-isolated.** Use a dedicated cookieless hostname such as `attachments.ust-rankings.com`, not the application origin. Set the detected `Content-Type`, `Content-Disposition: attachment` with a sanitized filename, and a conservative `Cache-Control` on the promoted object; Spaces stores those standard headers as object metadata. RFC 6266 says `attachment` asks the recipient to save rather than process normally, and RFC 6454 explains why a distinct scheme/host/port is a separate protection domain. Never reflect the upload's raw filename in a key or header. Do not grant delivery-origin CORS `GET` access. [Spaces metadata](https://docs.digitalocean.com/products/spaces/how-to/set-file-metadata/) [RFC 6266](https://www.rfc-editor.org/rfc/rfc6266.html) [RFC 6454](https://www.rfc-editor.org/rfc/rfc6454.html)

11. **Severity: moderate — direct Spaces/CDN delivery cannot be shown to add every desirable hardening header.** Spaces documents stored `Content-Type`, `Cache-Control`, `Content-Encoding`, and `Content-Disposition`, but not arbitrary response headers such as `X-Content-Type-Options`, CSP, or `X-Frame-Options`. Therefore do not claim those headers on a direct CDN object without an integration test. Download-only disposition plus a separate cookieless origin is the low-cost baseline. If later requirements demand `nosniff`, CSP sandboxing, or inline previews, put a tested header-setting delivery proxy in front (and model its bandwidth/availability cost) rather than serving inline directly from Spaces.

12. **The CDN helps only public delivery.** Public promoted objects can use the included Spaces CDN and a custom TLS hostname. Presigned CDN requests are not cached—every request reaches the origin—and DigitalOcean warns this can double bandwidth charging without cache benefit. Thus do not use private presigned GETs as the normal public delivery path. Object keys must be immutable because the CDN can cache responses; purge explicitly on emergency withdrawal and make the database/UI stop emitting the URL immediately. [Spaces CDN behavior](https://docs.digitalocean.com/products/spaces/how-to/enable-cdn/) [SDK/CDN warning](https://docs.digitalocean.com/products/spaces/reference/aws-sdks/)

13. **All uncertainty and dependency failure must fail closed.** Model `reserved → uploaded → scanning → clean | rejected | scan_error`, and publish only `clean`. Missing object, size/type mismatch, scanner timeout/crash, stale/unavailable signatures, managed API timeout/rate limit, inconclusive result, or database/storage failure leaves the attachment non-public. Retry transient errors with a bounded queue/backoff; after the limit, show the uploader “attachment unavailable” and retain briefly for operator retry or delete it. Review text may publish independently, but attachment links must not. Do not fall back to unscanned publication, an old verdict for different bytes, or a public scanning service. Availability is deliberately lower than Review availability.

## Proposed production pipeline (once scanning is funded)

1. **Reserve:** transactional per-User byte reservation and opaque attachment ID in Neon; enforce the 32 MiB aggregate across stored objects and live reservations.
2. **Upload:** short-lived presigned single-part `PUT` to a private `quarantine/` key at the Spaces origin; narrow CORS.
3. **Verify:** server `HEAD`; reject mismatch; enqueue by durable database state (polling makes retries idempotent and avoids relying on unverified Spaces event notifications).
4. **Identify and scan:** isolated scanner streams at most 32 MiB, hashes, content-identifies, structurally validates, and runs current ClamAV definitions. No transformation.
5. **Promote:** server-side copy to an immutable public key with canonical download metadata; verify, commit clean association, delete quarantine source.
6. **Deliver:** public CDN on a cookieless attachment origin, download-only; UI emits links only for clean rows.
7. **Clean up:** retry errors; delete rejected/expired/orphaned objects; prefix lifecycle is a final backstop; purge CDN and suppress links on moderation/withdrawal.

## Cost decision

| Option | Verified fit | Incremental/base cost consequence |
|---|---|---|
| ClamAV inside chosen 512 MiB app | No: far below 3–4 GiB recommendation | No added bill, but unsafe/unreliable |
| Separate 4 GiB DigitalOcean Droplet | Technically plausible after load/security testing | +US$24/month; total at least US$34/month including US$5 app and US$5 Spaces |
| Separate 4 GiB App Platform service | Technically plausible after testing | +US$40/month; total at least US$50/month |
| Cloudmersive free | No: 3.5 MB/file and not its production recommendation | US$0, but fails 32 MiB and production requirements |
| Cloudmersive premium | File-size/production path available subject to privacy review | Starts +US$19.99/month; exceeds ceiling |
| VirusTotal public | No: licensing, privacy, and “not an antivirus substitute” | US$0 but prohibited/unsafe for this use |
| VirusTotal/OPSWAT private | Potentially, after contract/privacy review | Quote/paid; no official price verifies ceiling fit |
| AWS GuardDuty for S3 | No: only the account's Amazon S3 buckets | Would require moving/copying storage and adds services/cost |

The least expensive verified self-hosted total is therefore approximately **US$34/month**, not US$10/month. Taxes, backups, monitoring, and operational labor are excluded. A lower unverified spot/serverless construction would introduce variable cost, cold-start/signature-mirror complexity, and no demonstrated production availability; it is not recommended as the “simple” pipeline.

## Gaps and required validation

- DigitalOcean does not document arbitrary security response headers for direct object/CDN delivery; capture real origin and CDN responses before launch.
- No source can prove universal semantic file identification or absence of malware. Final allowlist, parser behavior, ClamAV archive limits, timeout, concurrency, and false-positive handling need adversarial fixtures and load tests.
- Confirm `CopyObject` ACL/metadata replacement, lifecycle prefix behavior, CDN withdrawal/purge latency, CORS preflight, and presigned-header enforcement against a non-production Space.
- Obtain written managed-scanner quotes/DPA/subprocessor and Hong Kong cross-border review if managed scanning is reconsidered.
- The 32 MiB quota bounds each User's stored objects, not total Users or bandwidth; monitor the Spaces 250 GiB/1 TiB included allowances and abuse patterns.
